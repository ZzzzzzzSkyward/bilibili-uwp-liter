## Supported defect and required behavior

The complete actual `Utils.ShowLoginDialog` sets `dialogShowing=true`, awaits native `LoginDialog.ShowAsync`, and clears the flag only after normal completion. A delivery fault therefore leaves the static flag set. The repaired real `RecommendVM.Dislike` correctly contains that exception, but its next logged-out action cannot display a later available successful dialog. The retained same-process proof has four passing controls and one genuine retry failure: native show count stays3, requests0, original row retained, account false. This is FA-09/P2; no particular Windows exception occurrence is asserted.

The invocation that enters the existing `if (!dialogShowing)` branch and sets the flag owns that show attempt. Release its flag in a `finally` around its native show await, within that owning branch. Keep the existing dialog construction before the assignment, claim before calling `ShowAsync`, and account/bool tail. A branch-local finally needs no new global owner, lock or credential mechanism. A finally enclosing a nonowner invocation would be incorrect: it could release someone else's held show.

| Path | Contract after the amendment |
| --- | --- |
| Owned ordinary completion | Clear the owner's flag on both login success and normal user cancellation. Continue returning current `SettingHelper.Account.Logined`, true/false respectively. |
| Owned synchronous delivery throw or faulted native task | Clear the owner's flag and propagate the original exception through the helper task; do not replace it with false, swallow it or change caller error policy. |
| Owned cancelled native task | Clear the owner's flag and preserve cancellation/its token through the helper task. The existing caller may still contain it under its current error boundary. |
| Call while a show is held | Do not construct/show another dialog, wait for the owner, or clear its flag. Preserve the existing immediate result from current account presence; logged-out nonowners return false. Another call while that same owner remains held must also be suppressed. |
| Later call after owner success/cancel/fault/cancellation | Once the account is logged out and a native outcome is available, the helper is usable again without process restart or product-state repair by the fixture. |
| Already-logged-in real action | Preserve the caller's existing account check and dialog bypass; preserve real request fields and row handling. Do not introduce a new account short circuit inside the helper. |

No signature, field, public bool, account parser, credential commit/token/cookie behavior, native login dialog, UI, framework, concurrency policy, schema, request policy or caller product changes are needed. This preserves existing UI/reentrant overlapping-call behavior; it does not introduce a cross-thread serialization guarantee.
