## 1. Minimal behavior contract

**FA-05 / P1 — ordered distinct MultiFLV destinations.** The real ParseJson → PlayerVM.GetPlayUrls → DownloadDialog → AddDownload/SaveInfo path must produce one destination for each ordered FLV entry. Name the first segment `0.blv`, the second `1.blv`, then `2.blv`, etc., advancing once for each appended request. Preserve the actual mapper list order and each entry's URL and headers; SaveInfo.VideoPath must contain those same names in that order. Do not sort/reinterpret wire `order`, deduplicate sources, change `.blv`, collision options, folder naming, single-FLV `0.blv`, DASH `video.m4s`/`audio.m4s` or the existing video-only DASH naming. No parser, format, playback/export or transfer redesign is required.

**FA-06 / P2 — required-media validation precedes admission.** AddDownload retains its public awaited Task/preparation contract. A missing request, null/empty required Urls list, or unusable required entry must fail the whole preparation with actionable caller feedback. A null entry, missing source/filename or source that cannot form the existing transfer URI must not be counted as media or silently filtered into a zero-operation success. Validate detectable input failures and existing child-name rules before creator admission/revision/generation changes and before target title/episode/auxiliary/media/metadata writes; keep existing URI/protocol compatibility rather than adding a CDN policy. The original harmless common default-root OpenIfExists exception remains permitted.

In particular, actual `durl=[]` currently maps to successful MultiFLV with zero entries: leave that mapper unchanged and reject the real dialog's resulting empty list at the helper boundary. Preserve exact old metadata/media/GUID settings, creation/evidence stamps, known partial marker and CleanupFailures target. No new CompletedRevision/success proof, successful dialog State2, cleanup retirement or completed publication may result. The existing dialog exception path must leave State99/text/action enabled and failure feedback. Zero required operations must never constitute successful replacement evidence, even if preparation settles; a narrowly defensive coordinator guard is allowed. Do not replace a known partial with a newly admitted empty generation and then try to compensate after metadata writes.

All nonempty preparation/observer/lease rules remain: settle required siblings and SaveInfo/start dispatch, discover successfully admitted siblings after a partial failure, require every required transfer of the current successful generation before supersession, and reject old cleanup/completion authority over newer work. Valid nonempty retry, genuine successful replacement and validated cleanup still recover normally. Optional auxiliary tolerance, disk schemas/settings, headers/group/network behavior and media-lifetime lease prohibition remain unchanged.

**FA-07 / P2 — truthful typed failure and retry.** A typed playurl failure is a failed selected row just like the existing preparation-exception branch: retain State99 and its actual error text, notify `PropertyChanged("ErrorMessage")` because the XAML binds ErrorMessage, keep the dialog open, restore the primary action and issue failure feedback instead of `已添加至下载列表`. A failed selected row prevents all-success close/toast even when a sibling succeeds. Refresh discovery of already admitted siblings through the existing DownloadVM path; their operations/metadata remain discoverable. An explicit retry processes State0/99 rows and skips already admitted State2 siblings, with no duplicate playurl/admission/operation for those siblings. Once every eligible selected row succeeds, retain the established success toast/close behavior. Preserve zero-selection warning, enabled action, zero operations and open dialog. No XAML/property rename or dialog framework is needed.

**P2-CR1 — initiating selection and the whole async event are owned.** Before the first await, capture a concrete ordered snapshot of the initiating selected DownloadEpisodeItem objects; iterate that snapshot while retaining the original State0/99 eligibility and State2 retry skip. Subsequent clear/add/select-all/hide-preview changes belong to a later activation and cannot remove, add or retarget this invocation's selected objects. Enclose the complete async primary event, including selection capture, iteration and final reporting/discovery, in an exception-contained boundary; per-item catches alone cannot contain iterator or other batch failures. Restore IsPrimaryButtonEnabled in finally. An unexpected batch failure keeps the dialog open with useful failure feedback and attempts the existing DownloadVM discovery of admitted siblings, without allowing discovery/reporting errors to bypass restoration or escape async-void. Preserve zero-selection, all-success close/toast, typed/preparation/mixed failure and duplicate-free explicit retry semantics. No XAML disabling, framework or new scheduler is required. The released proof supports this source-contract failure; it does not establish a particular native iterator's behavior or a Windows crash.

**FA-08 / P2 — honor actual login success and selected-row ownership.** Actual Utils.ShowLoginDialog returns true after logged-in success and false if still logged out. For a logged-out user, proceed with the intended dislike/feedback only on true; false/cancellation/exception must construct/send no action request and mutate no feed row/state. Keep useful existing failure/login feedback and the exception boundary. Already-logged-in actions bypass the dialog and retain their current request fields, acknowledgement parsing and behavior. No Utils, credential, account-parser or authentication policy product change is authorized.

Capture the current Items collection and selected row object for idx **before the login await**; a missing row is a safe no-op. After successful login, recheck that collection is still current and still owns that object **before constructing/sending** the action. A refresh producing a different collection with the same idx, or removal of the selected object during login, ends the old action with zero action requests and no replacement-row/state mutation. Do not reacquire the target by idx after login. Retain the existing post-acknowledgement collection/object check too: a replacement while the action request itself is pending stays protected. Ordinary success still removes only its owning row and preserves Ready/empty/nonfinal/pending/error/explicit-retry/no-progress feed rules and feedback_id versus reason_id.

**P2-RF2 — implement the already approved FA-02 classification rule.** No additional contract/schema is needed. Exact known partial/pending episode classification cannot depend on constructing a DownloadedSubItem. Carry enumerated exact-path read/classification evidence through missing/unusable metadata, missing media and initial zero-length-media exits and through the final no-await publication recheck. Such an exit must not lose a later cancellation/pending-generation change during a storage await. Withhold the title whose only relevant candidate is that known remnant and retain the truthful partial/cleanup-pending status and recovery target; keep valid siblings visible. A later validated cleanup or fully successful current nonempty replacement permits a truthful refresh. Preserve unrelated tolerant legacy/empty-folder/metadata skips and existing successful generation/current-owner/stale-snapshot controls. Do not add a blanket title/root filter or claim every unrelated empty folder is unfinished.
