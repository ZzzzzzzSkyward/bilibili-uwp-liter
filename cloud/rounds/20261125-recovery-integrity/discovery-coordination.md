# Discovery coordination

Root asks each specialist to checkpoint any current confirmed red evidence and ruled-out hypotheses into its own evidence.md while finishing requirements, so stage/ownership planning need not infer results from scratch processes. No need to exhaust the entire repository before this round can fix a bounded feature. Prioritize the strongest reproducible recovery/integrity defects; distinguish broader source observations that should remain explicitly triaged from the concrete execution slice.

Storage contracts should inspect actual entry mutation/callers, deep versus shallow snapshots, persisted write order/failed-write recovery, registry transaction/temp-file ownership, access-token commit/rollback/retirement and concurrent reopen/read semantics. Boundary contracts should preserve ordinary scalar and optional-default behavior while covering true overflow/BigInteger paths without invented coercion. Recovery contracts should retain known-good rows/cursors until success and use exact actual methods/source in tests, with only primitive platform/transport stubs. No source/test/main-doc/index mutation until all discovery outputs pass independent requirements review.

Keep product UWP project explicit Compile entries and actual language/API compatibility in view if proposing new files. Prefer existing owning batches and actual-source test seams; if a new physical stage is warranted, declare the exact manifest/control/docs inventory change under one executor instead of masking it. All tests generated/extracted from real methods must bind exact source ranges and remain out of tracked product code. Existing baseline toolchain is installed; no need to rerun the whole unchanged suite during requirements.
