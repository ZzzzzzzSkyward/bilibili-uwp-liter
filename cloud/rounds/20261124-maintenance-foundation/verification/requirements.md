## 2. Goals and non-goals

Goals:

1. Make every existing probe reproducible from declared prerequisites and report every batch/stage, including failures after an earlier failure.
2. Repair stale harness compile inputs and stub contracts without changing product behavior, reducing assertions or hiding failures.
3. Give U1 and later changes area-specific regression gates, a whole-suite gate and a separate Windows/device gate.
4. Record SDK, source SHA, platform, command, outcome, failure classification and evidence consistently; distinguish confirmed defects from hypotheses and external limitations.
5. Establish incremental CI, release validation, dependency review and documentation ownership with measurable maintenance cadence.

Non-goals: changing the branch/release model; publishing or installing packages here; declaring device acceptance; global dependency/framework migration; account-parser migration; player/SMTC/pacing redesign without measurements; touching identities/signing material, live JSON, protos or binary assets; weakening assertions to obtain green output. Existing maintainer acceptance in `plan/VALIDATION.md:6–12` remains authoritative; historical accepted rows are not reopened by this baseline.
