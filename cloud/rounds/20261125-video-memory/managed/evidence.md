## Actual ownership/close graph

- Static `MessageCenter` shell events → one MainPage/NoTab shell (intentionally view-lived). There is no per-video subscription in those shell constructors. MainPage tabs → TabViewItem → MyFrame → current Page/content/cache. `MainPage.ClosePage` clears current Grid children, invokes `MyFrame.Close`, nulls TabItem.Content, removes the tab. The disabled comments about BackStack/GC are not active code. A dropped, unreachable frame can collect its cache/owned event cycles without explicitly clearing every back-stack entry.
- `MyFrame.ClosedPage` is frame-owned, not static. Video and Season register idempotently and remove the handler in Close/OnNavigatedFrom. Local's ordinary close handler does not remove itself, but that edge is within a discarded frame/page cycle; source-slice weak tests collect it.
- View-scoped `DataTransferManager.DataRequested` → Video/Season page is a real long-lived root while subscribed. Both pages' actual Close and OnNavigatedFrom call `ReleaseShare`. Negative omitted-close tests retain pages through this event and release them through the real close method. Video page key input registers idempotently at Loaded and detaches at Unloaded; actual native unload delivery is not simulated/proved by the share fixture.
- NoTab shell → `NewInstanceFrame.Children` → one or more MyFrames/history. Duplicate page types create a new frame; otherwise the current frame navigates. A forward navigation pauses the old PlayPage and intentionally retains it for Back. Back disables the outgoing cache and either goes back/clears ForwardStack or awaits its animation then closes/removes the extra frame. Required/Enabled cache policy is explicit in source, but the WinRT Frame cache is not executed by a Linux fixture.
- Page → VM → instance RelayCommand delegate → VM and instance PropertyChanged handlers are owned cycles. `PlayerVM` creates its own API/play-url helpers and fixed 14-color list; no static VM/page collection or timer is present. BiliPlayUrl creates a request per call rather than caching every opened video's response. No global HttpResults history was found in this caller path.
- Video page close marks `_isClosed`, closes transition generation, clears queue/sequence/media-list loader references and share subscription before disposing. `PlayQueueState.Clear` cancels its load-all runner and nulls playlist/paging/rows/loadAll. `MediaListPageLoader` is single-flight and clears its pending task in finally. Its fetch delegate can retain the page only while an in-flight fetch/runner remains rooted; append state can finish privately after close, but the page drops its owning references and page guards reject late presentation. No perpetual list root is established by this graph.
- Static PlayerControl `_activeInstance`, CoreWindow/SMTC, timer and native engine lifetimes are in the resource owner's scope. Current source sets the active field on Loaded and conditionally clears it on Unloaded. This stream neither infers a leak from that field nor claims native unload disposal is proved.
