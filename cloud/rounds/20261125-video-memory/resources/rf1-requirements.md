## Problem, goal and minimal decision

A constructed PlayerControl legitimately has no `CurrentPlayItem` until public initialization succeeds. Its enabled Update Danmaku handler awaits complete `SetDanmaku(true)`. The private current-work helper currently accepts `(null,currentGeneration)` when CurrentPlayItem is also null; SetDanmaku then dereferences that null before its try. The actual async-void click posts a NullReferenceException. The same safe click fixture passes the earlier8682 source and fails this284be source while its ordinary current-item control remains functional.

**Require a real, non-null item for playback work.** Prefer strengthening the existing private `IsPlaybackWorkCurrent(item,generation)` predicate to reject `item == null`, retaining its terminal, generation and reference checks. All inspected callers use it to authorize item-owned producers/publication; none requires null to mean a valid current owner. Do not add a cid/avid/LocalPlayInfo requirement: valid local/manifest items and accepted generation0 test/live contexts keep their existing semantics. An explicit SetDanmaku null entry guard is an acceptable equivalent only if it rejects before all item-dependent precheck/lease/request/publication work and the actual caller controls still pass; no broader helper refactor is needed.

An absent owner is a quiet no-op: no request or file access, new guard/lease, pool/segment/settled-state mutation, renderer/visibility publication, success/failure toast or exception. A no-item click must neither fabricate a PlayInfo nor advance a generation/reset a terminal flag. Returning only in the XAML handler, hiding the button, or moving a new failure into a broad catch is insufficient for the SetDanmaku producer boundary. Do not change the currently supported active failure/reporting policy.

Non-goals: new page/loading UX, new button policy, page/VM changes, catch-and-ignore wrappers, nulling a live item to evade work, new cancellation/dependency/project/stage, native/player rewrite, cache purge/GC, or new memory attribution. The existing FA2 node-initial phase and owned lease must still reject skipped/current/stale calls correctly. Current-item manual refresh remains functional; terminal close remains terminal; all prior positive playback/graphics/history/season/tooling/API assertions stay intact.
