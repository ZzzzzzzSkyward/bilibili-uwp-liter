The lifetime fixture compiles complete actual InitializePlayInfo, SetPlayItem, Loaded, Unloaded, Dispose, opened/manual subtitle/public index, all three settings loaders and relevant info/quality/local-open/node/import/danmaku/engine paths. The terminal latch and settings flags are extracted from actual source when present; the fixture never resets them. Public live/fresh/same-reference positive cases traverse the actual initialization chain through actual SetDanmaku→SetQuality→ChangeQuality→GetPlayerInfo→SelectInitialSubtitle→SetSubTitle. New owners are constructed; disposed owners are never reconstructed or treated as reusable.

The fixture's constructor supplies UI/platform/network/media dependencies, rather than emulating InitializeComponent or native UWP construction. UI elements count assignments and raise value/toggle/selection events; settings store reads/writes, network requests and media open completion are controlled. Actual PlayerSessionState, LocalMediaAsyncLoadGuard, history sources and complete track-switch coordinator are compiled. The coordinator's only textual substitution is its parameter type `LocalPlayInfo` to the fixture `LocalInfo`; mutable selection setters are an explicit dependency model. This proves control/callback/coordinator ownership behavior, not native decoding or a new claim about the unchanged selection helper's full track conversion. Interaction VM request completion is a boundary double; a pending old VM's detachment is checked at the real control binding sites. Actual page/shell/cache methods and the new caller gates belong to the managed workstream and are not replaced by player no-op behavior.

`DispatcherTimer.Running` deliberately models a live external dispatcher root. Weak-reference setups use NoInlining, return only WeakReference lists and complete all request gates before collection. Creator locals/tasks/frames are gone. The active50 control remains rooted; stopping modeled roots releases those controls. GC/finalizer waits appear only in weak-reference assertions, never in app code or the graphics fixture. The settings control is unloaded before its creator returns, so an internal event cycle is not mislabeled as an external leak. All gates are completed/canceled/faulted in controls; no pending test jobs are used as survivor proof.

Graphics stubs track acquisition/release, consumed-open requirements, exact release order/counts, original exception object references, drawing/PNG/source/stream order and rendered output graph usability. The final actual method completes50 renders with all50 output graphs retained/read, zero shared-device closes and zero undisposed owned temporaries;50 actual-source-versus-original parameter/output traces match. Fault controls cover23 acquisition/setter/drawing/stream/output points and two genuinely suspended completion faults. A stub close fault marks drawing closed before throwing; it does not establish native cleanup under a Close/Dispose failure. No fixture measures pixels, GPU allocations, native handles, wrapper finalization timing or process RSS.
