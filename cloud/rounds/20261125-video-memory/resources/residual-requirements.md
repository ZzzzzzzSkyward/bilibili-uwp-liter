## Ownership contracts

### PF1/P1 — accepted replacement owns track and Next eligibility

`SwitchLocalTrackAsync` owns its temporary disabled state while its captured item/generation is current. `SetPlayItem` advances generation and clears `_localTrackSwitching`; it must also transfer the normal usable selector/Next state to the accepted replacement, rather than depending on the obsolete switch's finally to do so. A distinct or same-reference B with usable manifest tracks and no switch of its own must become usable independently of whether A ever completes. Current failed/faulted/canceled switch recovery retains its existing rollback/diagnostic policy.

Keep the stale finally guard and shared LocalPlayInfo protection: A must not enable, alter flags, change selected tracks, trigger rollback/open/dialog, or refresh B's UI while B's own switch is pending. Only B's matching completion restores B's switch-disabled state. Terminal close never performs a re-enable or makes an owner live again.

Eligibility composes the **current** facts, rather than storing an old `IsEnabled` snapshot or unconditionally assigning true: the selectors retain their existing normal option/visibility policy and are unavailable during the current track switch; Next stays disabled while either the current track switch or `_transitionPending` owns that restriction. `ShowTransitionPending` and `ClearTransitionPending` are existing competing Next writers and must honor the same rule if a shared helper is introduced. Their labels, visibility, directory behavior and page transition policy remain unchanged. Clearing one reason must not release the other reason. Do not invent a new rule that an empty/hidden selector is globally disabled if the existing UI policy does not require it.

### FA1/P2 — revoke terminal interaction view ownership; permit finite detached work

Choose **detachment in PlayerControl**, not a new child-VM cancellation/generation API. After setting the monotonic terminal latch, synchronously clear the owning `interactionVideoVM`/`_interactionVideoItem` identities and both `NodeList.DataContext` and `InteractionChoices.DataContext`, before other resource-close callbacks/history awaits can run. Required Unloaded cleanup still runs normally. Repeated close remains safe. Detach operations can themselves raise ordinary UI notifications; the terminal latch is already set so reentrant callbacks cannot authorize new work.

An already-started real `InteractionVideoVM.GetNodes` may finish transport/decode and publish Info/List/Select/Loading **only to its detached old VM**. This amendment deliberately does not promise cancellation, no internal child notifications, no finite child allocation, or no existing error log. Actual GetNodes handles errors via IModules.HandelError, whose inspected behavior returns/logs an error without invoking a player/global UI toast. Parent identity/generation/child checks continue to reject the old title/online/subtitle/player suffix. No old child may remain bound or be rebound to this closed control or B.

Preserve active interaction publication and node navigation, plus the already accepted detachment on distinct/same-reference SetPlayItem replacement. This contract does not claim arbitrary concurrent GetNodes operations on one still-bound live child are latest-wins; no such child API redesign is included. If a newly exercised supported caller proves another current-child race, return its complete source counterexample for a precise amendment rather than silently expanding into a VM rewrite.

### FA2/P2 — node generation owns pool, segment eligibility and one load lease

Advancing an accepted ChangedNode operation must revoke the previous node's danmaku pool/list/settled/load ownership, even though the PlayInfo reference is reused and its cid is changed in place. New-node list/snapshot/render input must not interpret an old-node cue or `loaded segment1` mark as current data. The new node must issue/accept its own cid segment1 after its node step, while an obsolete segment request can still be pending. Existing generation rejection of the old response remains mandatory.

Make the current load restriction an **owned lease**, using captured generation/cid and, where needed, a per-attempt identity or acquired marker. A call that returns without acquiring the lease must not clear it in finally. An old success/fault/cancel/finally cannot unlock a newer request or alter its pool/list/settled/UI state. Within one current node, repeated/timer/manual requests retain the intended single active segment-load behavior; this is not permission for unbounded parallel loading.

Handle the initial-node phase deliberately: old playback position/timer pressure must not start a different segment that makes the new segment1 disappear behind another lock or old loaded mark. Deferring normal segment polling until current initial-load ownership is established is acceptable; preserving an explicit initial-segment request/eligibility state is also acceptable. No artificial timer/decoder reset or network cancellation is required. A successful current segment1 marks only its own segment, supplies its own cues and permits later current segments. A failed current load does not falsely mark a segment loaded; existing active failure/manual-update behavior remains usable, with no stale result or stale unlock. Keep manifest/import local-track guards and live manual segmented refresh unchanged.

### FA3/P1 — history await does not transfer ended ownership to B

`Player_PlayMediaEnded` must capture original item plus work generation and verify the terminal/current contract **before** acting on an event, before its history await and after that await before any suffix action. Same-reference media reuse is not a current-operation check by itself. An entry that was valid for A and becomes obsolete while its real history report is pending may finish that already-started report but must not emit AllMediaEndEvent, start another part/sequence, play/loop, change subtitle/danmaku/choice UI, write `_autoPlay`, or produce a new completion toast for B/the closed owner.

Preserve the final history report for A at its original duration/identity, manifest skip, synchronous local history save on close/flush, and the existing serialized checkpoint/latest-tail mechanism. Do not cancel shared history, wait for it during close, duplicate the report or change the service's existing `reportErrors` policy. Existing service error handling belongs to that report; the obsolete **ended suffix** remains quiet. A handled history transport failure still permits the normal active-owner end behavior. Any unexpectedly propagated report exception must be contained/logged at this touched async-void boundary; after handling, recheck ownership before any active continuation. No unhandled async-void fault or stale end action is acceptable.

After validation, keep the current owner's existing play-mode/user-choice semantics: ordered last-item event or existing completion message; allowed next-part starts at FromStart; AUTO_NEXT off remains stopped; single/list loops retain their existing clears/play/index actions; manifest mode skips remote history; interaction leaf/nonleaf behavior remains intact. Do not snapshot another owner's current controls after await, but do not freeze an old play-mode preference when the same still-current owner legitimately changes its setting while reporting. No global event-argument/API rewrite is needed: actual VideoDetailPage receives AllMediaEndEvent and uses its live current sequence, which is why the control must suppress an obsolete event.
