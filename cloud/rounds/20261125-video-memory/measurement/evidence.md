## Official tool references checked

Used the currently available `search_service.web_run` search/open interface on 2026-11-25, restricted to official Microsoft documentation; no Firecrawl, browser session or deep-research skill was required for these narrow API checks. The references support collection choices, not a claim that installed Windows tools were tested.

* [Process.PrivateMemorySize64](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.privatememorysize64): property equals Private Bytes; refresh before reading. [WorkingSet64](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.workingset64): currently resident pages include private and shared pages. These values cannot be interchanged.
* [Visual Studio memory usage](https://learn.microsoft.com/en-us/visualstudio/profiling/memory-usage?view=vs-2022): managed/native snapshots and Paths to Root; native/mixed heap profiling must be enabled and the debugging session restarted. Actual attach/heap availability depends on target/runtime/tool support and must be recorded. [Choosing a memory tool](https://learn.microsoft.com/en-us/visualstudio/profiling/analyze-memory-usage?view=visualstudio) includes installed Store app/running-process targets.
* [WPR command line](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/wpr-command-line-options): enumerate local profiles/help; HeapTracingConfig supports process plus packaged full-name/app-ID fields and should be disabled after tracing. [Recording for heap analysis](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/recording-for-heap-analysis): setup before trace, Heap start/stop, package full name differs from family-name AUMID. [Resource profiles](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/recording-for-resource-based-analysis): Heap and VAlloc are distinct. Never claim a generic trace includes all native/GPU allocations.
