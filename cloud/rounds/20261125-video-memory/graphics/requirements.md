# Per-cue subtitle graphics ownership requirements

Status: RELEASED for independent requirements review; no execution grant. Supporting facts, commands and limitations are in [evidence.md](evidence.md). This extends the resource workstream only if independently accepted. It creates no second `PlayerControl` source owner.

## Background, classification and goal

`GenerateSubtitleItem` runs during ordinary subtitle cue changes (`SubtitleTimer_Tick`) and subtitle setting refreshes (`UpdateSubtitle`), including when playback is successfully open and no close race occurs. It owns five fresh Win2D objects per invocation but explicitly closes none: `CanvasTextFormat`, `CanvasRenderTarget`, `CanvasTextLayout`, `CanvasGeometry` and `CanvasStrokeStyle`. The actual published UAP WinMD and projected API documentation for `Win2D.uwp`1.26.0 support disposal of **all five**, including format/style. The device returned by `CanvasDevice.GetSharedDevice` supports disposal too, but is borrowed and must remain open.

G1 is a confirmed absence of deterministic per-call resource release (E1, P2 ownership hardening), and a candidate contributor to transient/finalization/native memory pressure during watched playback. It is **not** a proven permanent leak, measured native allocation slope, or attribution of the user's50-video growth. Exact-version upstream `ResourceWrapper` has destructor cleanup; timing of native destruction, .NET/UWP wrapper release, GPU work, driver memory and caching remains unmeasured. Keep G1 separate from resources R1/R2 late-close work creation and R3 same-owner settings-handler amplification.

Goal: end each successful or failed render's ownership of its acquired temporary Win2D resources deterministically, while retaining all existing render parameters, operation order, output ownership and async completion semantics.

Non-goals: subtitle renderer/UI rewrite, caching/debouncing/concurrency changes, changing generation/lifetime policy, closing shared devices or returned XAML images, production GC/finalizer waits, graphics cache trim/purge, device-loss policy, dependency/version/language changes, decoder/danmaku/native stream repair, claiming native bytes or pixels from stubs. Existing async-void caller fault reporting is a separate concern; this slice preserves GenerateSubtitleItem's exception propagation instead of adding swallowed failures or UI behavior changes.

## Verified API and ownership contract

The source references `NSDanmaku`2.2.0, whose official nuspec requires `Win2D.uwp >=1.26.0`; Toolkit Controls7.1.3 → Media7.1.3 requires `>=1.25.0`. Source has no direct Win2D pin and no restored assets/lockfile. Evidence verifies the actual1.26.0 UAP WinMD, not an imagined local Windows restore. The eventual executor must record the actual resolved package/assets and Windows compile result when available, without changing dependencies merely to support this repair. Windows compilation remains externally blocked here; this is not a source/API reason to invent new disposal contracts.

| Value | Ownership and supported release | Required lifetime |
| --- | --- | --- |
| `CanvasDevice.GetSharedDevice()` | Borrowed shared device, `IClosable`/projected `IDisposable`; **do not close it**. Upstream docs explicitly warn about breaking other consumers. | Valid for the whole call and later unrelated rendering. Closing owned resources only drops their device references; upstream `ClosablePtr.Close`/bitmap close do not invoke shared-device Close. |
| `CanvasTextFormat fmt` | Owned per-call object; actual WinMD `IClosable`; Dispose documented. | Acquire scope immediately after its constructor, with property initialization inside that scope so setter failure cannot strand the acquired format. Remain open through all consumers. |
| `CanvasRenderTarget myBitmap` | Owned per-call bitmap; derives `CanvasBitmap`, which implements `IClosable` and projected Dispose. | At least through drawing-session close and the awaited PNG save; proposed conservative scope holds it until source loading/output assembly ends. |
| `CanvasTextLayout` and `CanvasGeometry` | Owned per-call `IClosable` objects; Dispose documented. | Valid while text geometry is created/drawn; conservative scope holds both through source completion and output assembly. Reverse acquisition release is safe. |
| `CanvasStrokeStyle` | Owned per-call `IClosable` object; Dispose documented. | Acquire at the existing point after Clear, and keep open until drawing session has closed. Enclosing `try/finally` with a nullable local preserves creation timing and covers DashStyle setter/render errors. |
| `CanvasDrawingSession` | Already owned/scoped with `using`; retain this. | Must close before SaveAsync starts. Official render-target docs explicitly require this. |
| `InMemoryRandomAccessStream` | Already owned/scoped; UWP API projects `IDisposable`. | Open through awaited SaveAsync and awaited BitmapImage.SetSourceAsync; close afterward on success or fault. Preserve current order and scope. Official UWP SetSourceAsync example uses exactly this stream lifetime. |
| `BitmapImage` → `Image.Source` → returned `Grid.Children` | Output object graph transferred to caller/XAML; BitmapImage is a BitmapSource, not a temporary Win2D render target. | The caller can publish/retain it after temporary Win2D resources and stream close. Do not clear/close its source or the returned Grid in this method. A stale caller may drop the visual through normal XAML ownership. |
| Measurement `TextBlock` | Local XAML measurement object; not a Win2D closable temporary. | Keep existing Measure/DesiredSize behavior. Do not invent a Dispose call. |
