## P1 — AS3 promises incompatible behavior for an empty append without has_more

**Location:** [contracts/requirements.md](contracts/requirements.md), AS3 “Required behavior” and “Acceptance”. The same paragraph requires that a first/append empty page terminates paging, then requires that absent/null `has_more` retain the existing count-based compatibility rule, explicitly including `!=` semantics. Those rules disagree for a normal favorite append with absent/null `has_more`, zero decoded rows, one previously accepted row and `FavoriteInfo.media_count=42`.

**Actual current behavior:** [FavoriteDetailVM.cs](../../../src/BiliLite.UWP/Modules/Detail/FavoriteDetailVM.cs):118–183 appends no rows, evaluates `1 != 42`, sets `ShowLoadMore=true` and changes Page2→3. The same is true for Type21. My complete actual-VM boundary probe independently confirms both absent and explicit-null cases, and confirms that malformed/failed appends retain accepted rows/info/Page. A generic early return on `data.medias.Count==0` would alter the promised absent/null fallback and Type21 compatibility. Conversely, placing that guard only inside a present-boolean branch would violate the unqualified empty-page sentence. Root [scope-decision.md](scope-decision.md) preserves source distinctions but does not settle this boundary.

**Required correction before PASS:** Have the requirements author state an explicit decision table for normal-versus-Type21, present true/false-versus-absent/null, and empty-versus-nonempty decoded page. State which rule takes precedence and exactly what happens to `ShowLoadMore`, Page, existing rows/info and first-page empty state. Preserve Type21's existing count behavior. For normal absent/null empty append, either explicitly preserve the current fallback or explicitly identify the intended compatibility change and its bounded rationale; do not silently claim both. The existing AS3 true/false counterexamples and all original assertions stay required.

**Closing tests:** In the eventual unchanged final real-source `c2` fixture, include separate normal absent-empty and null-empty Page2/count42/one-existing-row controls, the present-true empty counterexample, a present-false empty case, and Type21 equivalents. If absent/null empty behavior changes intentionally, preserve those desired-safe assertions unchanged for original-source red→repaired-source green; if it does not, those are unchanged original-green controls.
