## FI1 — PGC index must own conditions and result loads

**User trigger and current failure.** `Pages/Bangumi/AnimeIndexPage.xaml.cs:24–47` constructs/uses `SeasonIndexVM`, awaits `LoadConditions()`, then awaits `LoadResult()`. A fresh VM starts `_loading=true`; conditions only release `ConditionsLoading`; `LoadResult()` returns at its `if (Loading)` before sending any result request. Its `finally` then makes Loading false. The initial page therefore finishes without fetching results, and only a later user retry/selection can fetch them. Separately, when one result request is held in flight, a second guarded call returns through that same finally and clears the first call's flag. A third call sends a duplicate request; both continuations publish/advance the shared page. The private full-VM counterexample proves both failures, including duplicate final rows/Page3 instead of one row/Page2.

**Required behavior.** A new VM starts with neither request owned: Loading is idle for results and ConditionsLoading is idle for conditions. Navigation with a nonnull Parameter must load conditions once, then request the first result once when usable selected metadata is ready. Conditions and results have separate, mutually excluding owners. Every public load/command entry must reject missing Parameter, conflicting ownership and premature/unusable metadata before it changes page/result state or emits a result-loading notification. Acquire each owner before synchronous notifications; only the acquiring invocation releases it. Rejected calls send no request, change no page/rows/flags and add no error. After condition failure, an idle legitimate Refresh can retry conditions once and then load results once. Keep conditions ownership through synchronous Conditions publication so the real selection handler remains excluded. Publish result rows and advance Page before releasing result Loading; a real grid completion callback may then acquire a legitimate page2 append. The normative entry/ownership table, structural readiness definition, failure/retry semantics and maintained acceptance are in [fi1-amendment.md](fi1-amendment.md). No generation/filter-cancellation architecture is added.

**Exact retained API/data contract.** `SeasonIndexAPI.Condition(int season_type)` and `Result(int page,int season_type,string condition,int pagesize=24)` remain GETs against `ApiHelper.API_BASE_URL` at `/pgc/season/index/condition` and `/pgc/season/index/result`. Keep the existing LoginKey/MustParameter app-family fields, `needAccesskey=false`, app signature and no-cookie setting. Keep `season_type`, `type=0`; result query uses **page/pagesize**, the existing encoded filter values and `sort=0`. Do not replace these with web-search `page_size`, app-search `pn/ps`, new host, WBI, cookie/auth or S3's differing type1 option. The current condition JSON path is `code` then **data.filter/data.order**; result is **data.list**. These are legacy `HttpResults.GetJObject`/JsonConvert VM reads, not typed PGC parser calls. No parser/envelope migration, `data ?? result` fallback or altered scalar/null/salvage policy is included.

**Success/failure/paging compatibility.** Keep the existing first-page replacement and nonempty append order, Page increment exactly once after each accepted nonempty result, empty-page stop without increment, business/transport/error notices and append retention/retry behavior.
