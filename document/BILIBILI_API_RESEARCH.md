# Bilibili API update and complement research

Researched on **2026-11-09** against local `dev` tracking `origin/dev`.

## Scope and evidence

- Local baseline: [`d8d0edcd5eae954bd251372da0ff48f85778ff4f`](https://github.com/ZzzzzzzSkyward/bilibili-uwp-liter/commit/d8d0edcd5eae954bd251372da0ff48f85778ff4f).
- Sibling: [`ywmoyue/biliuwp-lite`, `dev`, `ca2caddc597b3faf05b4dac6dcb226aa0694365b`](https://github.com/ywmoyue/biliuwp-lite/commit/ca2caddc597b3faf05b4dac6dcb226aa0694365b). The sibling README recommends developing against `dev`; this investigation uses its actual checked-out commit, not an assumed release version.
- [Endpoint catalog](BILIBILI_API_ENDPOINTS.md): **203 distinct HTTP method/route pairs** in sibling request builders, **8 gRPC routes**, plus companion WebApi and live socket dependencies. Of the 203 pairs, **165 already exist locally** and **38 have no exact local route**. Those 38 include replacement candidates and alternatives; they are not 38 confirmed broken/missing features.
- Both source trees were inspected, including request dispatch, cookies, callers, concatenated URLs, and renamed/moved classes. The sibling moved most builders from local `Api/` into `Models/Requests/Api/`; a filename diff would produce false gaps.
- This is a **source comparison and implementation backlog**. No Bilibili endpoint was called, no authenticated session was used, and no write operation was performed. A sibling implementation demonstrates a contract to investigate, not official API support or present server availability. Priorities below are based on source defects and affected existing features.

Default host below is `https://api.bilibili.com`; **passport** means `https://passport.bilibili.com`, **live** means `https://api.live.bilibili.com`, **app** means `https://app.bilibili.com`, and **vc** means `https://api.vc.bilibili.com`. Methods and case-sensitive paths are intentional.

## Implementation and validation boundaries

1. Fix U1 first with a pure request-construction check: parse generated forms for a nonempty dummy CSRF value and assert that `type`, `message`, `root`, `parent`, and encoded text remain separate fields. Verify direct web search keeps the real BUVID and that proxy behavior remains intentional (U5). Check app search includes a requested nonempty order (U8), and favorite-folder create/edit encode separate `ts` and `privacy` fields before signing (U9).
2. Port transport capabilities before C4/C8/C9: local `ApiModel` has `ExtraCookies`, but `Utils.Request` only merges them on GET; POST goes straight to `HttpHelper.Post`. The latter uses the platform cookie jar and hardcodes form content. A `need_cookie` flag alone does not implement POST cookie overrides or multipart. Verify actual outgoing cookies, CSRF, content type and field encoding with dummy credentials in a controlled transport. Do not conclude from the unused flag that the platform sends no cookies.
3. For U2, verify token/host-list parsing, a complete socket join payload, failure/cancellation handling and response-protocol decoding. For U3/U4, validate request/response schemas before replacing routes. These migrations need Windows/UWP integration checks and a consenting test session; static source comparison is insufficient.
4. For complement work, capture sanitized response fixtures for QR pending/expiry/success, ticket expiry/challenge, history/message pagination, image upload, favorites and group operations. Keep web-cookie and app-token refresh credentials separate. Test logged-out and expired-session failures without destroying another usable credential type.
5. This documentation commit changes no application code. Validation performed for the research consists of endpoint-set reconciliation, pinned source path/line checks, documentation-link checks and `git diff --check`. No build or app test is claimed, and no endpoint liveness or authenticated behavior is certified.
