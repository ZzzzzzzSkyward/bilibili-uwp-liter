# Actionable finding from original batch 008

## #105 — Closing a video page waits for history reporting before stopping playback

Target `Pages/VideoDetailPage.xaml.cs:113-125` invokes `player?.Dispose()` from `ClosePage`; page-close and back-navigation paths both reach it. `Controls/PlayerControl.xaml.cs:2582-2610` implements `Dispose` as `async void` and awaits `playerHelper.ReportHistory(...)` at line 2589 before it calls `Player.Dispose()` at line 2599. `Modules/Player/PlayerVM.cs:57-70` shows the history operation awaits the request Task. `Player.Dispose()` reaches `ClosePlay()` (`Controls/Player.xaml.cs:1686-1689`), which clears/disposes audio, video, and media resources (`:1547-1579`). A pending history request therefore delays local playback teardown.

The isolated C# test extracted the actual `Dispose` method and used a pending history Task and recording player stub. It observed player disposal as `false` while the Task was pending and `true` after completing it; the immediate-disposal assertion failed as expected. No HTTP, app run, or build was involved. This proves the cleanup ordering, not real-network delay or indefinite audio. The pinned sibling has the same ordering and was not used to establish the target result.
