1. **Daily checks eventually disable cookie refresh.** `src/BiliLite.UWP/Api/ApiHelper.cs:552-555` resets `has_inited_cookie` each day, but `NeedRefreshCookie()` increments `init_cookie_try_count` even after successful checks and never resets it (`395-400`). Starting with the sixth completed check, the retry limit overwrites a server-provided `refresh=true` with `false`. A long-running app can therefore stop refreshing cookies for the rest of that process. Fix: count consecutive failed checks only, reset the count on success, and apply the limit only to failures.

2. **Refresh confirmation sends the wrong request.** `src/BiliLite.UWP/Api/ApiHelper.cs:500-509` constructs `api3` for `/confirm/refresh`, but then awaits `api.Request()`, repeating the earlier correspondence-page GET. The confirmation POST is never sent, yet `_need_refresh_cookie` becomes false. Fix: send `api3.Request()`, handle its HTTP and JSON result, and only mark the refresh complete when confirmation succeeds.

3. **One failed refresh prevents subsequent attempts until cookie info is checked again.** `src/BiliLite.UWP/Api/ApiHelper.cs:438-439` clears `cookie_timestamp` before the first refresh request. If that request fails, the page cannot be parsed, or the refresh token is missing, the method returns with `_need_refresh_cookie` still true and the timestamp zero. The player then receives the cached true from `NeedRefreshCookie()` and calls `RefreshCookie()` again, which exits immediately and asks for another login. The daily timer eventually permits another cookie-info check, but ordinary retries cannot recover before then. Fix: keep the timestamp until refresh completes, or invalidate the cached cookie-info state on failure so the next attempt obtains a fresh timestamp.
