# Confirmed issue #625 — collection comments dispatch the dynamic ID as a video ID

For a source-supported UGC-season card, `DynamicGrpcMapper.MapUserCard` sets `basic.rid_str` to `source.Extend.DynIdStr` (`Helpers/DynamicGrpcMapper.cs:307-314`) while mapping the actual AID separately to `major.ugc_season.aid` (`:412-427`). `DynamicVM.ConvertToDisplay2024` copies `basic.rid_str` into `ReplyID` (`Modules/User/DynamicVM.cs:921-932`). The page comment handler classifies a `MediaList` tagged `合集` as `CommentType.Video` but leaves the object ID as `ReplyID` and sends it to `Utils.ShowComment` (`Pages/Home/UserDynamicPage.xaml.cs:132-147`). The adjacent `Season` case instead passes `OneRowInfo.AID` for video comments. The #625 report says collection videos in the dynamic feed cannot show comments; the maintainer later says the feature was implemented in v4.6.31.3201 and requests verification.

The assigned reviewer executed the actual target comment-handler fragment with a source-supported collection-card display fixture and recording `Utils.ShowComment`: it dispatched the dynamic ID as video OID while the mapped UGC source object retained the AID separately; the expected AID assertion failed. This confirms the wrong local argument, not the remote comment API response. Artifact: `work/upstream-bugs/unit-tests/batch-043/issue-625/`.
