## [#1216 — Terminal comment pagination can repeat the first page](https://github.com/ywmoyue/biliuwp-lite/issues/1216)

Target `Controls/CommentControl.xaml.cs:167-168` requests the next page using `cursor?.PaginationReply?.NextOffset`. After receiving replies, it appends them, increments `_page`, and shows load-more whenever the reply count is at least ten (`:211-228`). It does not check whether the response supplies a next offset. `CommentApi.CommentV2` uses the offset for pagination; incrementing `_page` does not supply a new cursor.

For a terminal page containing at least ten replies with no next offset, another click sends the initial null-offset request again and can append duplicate replies. The pinned sibling hides load-more when `NextOffset` is null. This supports the terminal-page contract used for this source finding; the historical video's exact response was not captured.
